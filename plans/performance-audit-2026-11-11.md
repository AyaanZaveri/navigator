Baseline: `3abf7dd`, including optimistic web-search (`a7a1d11`) and subtitle-selection changes (`3abf7dd`) that were uncommitted when this audit was conducted. ## What would make the largest difference

Prioritize less competing work and earlier useful results before adding more speculative requests. The strongest paths are: stop idle header pixel sampling; remove the watched-status metadata waterfall; budget full-route prefetching; reduce player clock/context fan-out; and reduce repeated chat rendering. Home rows should become usable independently of the slowest provider.

**Evidence labels:** Confirmed means the work/dependency exists in the current source. Profile means the mechanism exists but its user-visible cost or the best tradeoff has not been measured. Priority estimates leverage, not a benchmark result. Every proposed cache must have an owner, key, size/TTL bound, invalidation policy, in-flight deduplication, and account/credential isolation where applicable.

## Further hypotheses to measure before changing

- **Decorative GPU work:** the home gradient's `busy = !reduce || ...` loop in `components/gradient-ascii/gradient-ascii.jsx:833` keeps visible animation alive even on utility pages. Static/lower-quality utility-page treatment could reduce energy use. This is a deliberate visual tradeoff, not a proven bottleneck. It already stops when hidden/offscreen and respects reduced motion.
- **Image completion layout reads:** `components/artwork-image.tsx:31` reads bounds per completion for reveal decisions. Batch visibility classification only if mass completion shows forced-layout cost; don't replace a cheap read with many more observers without measuring.
- **Cold artwork single-flight:** poster/backdrop/logo may resolve the same ID/image-list on cold starts. TMDB already uses a persistent explicit cache; verify actual upstream concurrency/cache locks before adding another token-scoped map.
- **Movie credits reuse:** title details append credits and cast may fetch credits again. Movies can potentially reuse typed credits; series aggregate credits are semantically different. Warm URLs are already cached.
- **Browser stream re-ranking:** `lib/media/resolve-playback.ts:146` can repeatedly filter/sort as snapshots and probes arrive. Existing score caching/probe bounds are good. Consider incremental ranking only after a large-list CPU profile; preserve language/decoder rules.
- **Request-local session dedupe:** `getUser`/`getAuthData` decrypt the session locally; React `cache()` could share render-pass work. This saves local crypto, not a remote auth request. Keep it request scoped. [React cache](https://react.dev/reference/react/cache).
- **Partial Prefetching / Cache Components:** a separate, larger migration worth prototyping after bounded metadata caches and route boundaries are clear. The installed Next version has new APIs, but current config does not enable them. Do not assume new shell behavior or apply a global flag as a quick fix. [Adoption guide](https://nextjs.org/docs/app/guides/adopting-partial-prefetching).

## Recommended implementation batches

1. **Remove constant waste:** P01, P12, stabilize P04 provider inputs and chapters. Capture quiet-page CPU and player render counts before/after.
2. **Unblock useful results:** P02 bounded watched decoding, P07 independent home rows, P08 concurrent recommendations. Use slow-provider fixtures and preserve partial/error behavior.
3. **Intent and reuse:** P03 shared prefetch policy together with P09 safe metadata cache. Then P14 adjacent library pages and P17 model-list sharing. Measure current-page competition as well as navigation wins.
4. **Playback/chat hot paths:** finish P04 isolation, P05 cue lookup and P06 throttled/memoized history, P10 narrower context. Verify subtitle seeks/offsets and tool/Stop immediacy.
5. **Payload and scale:** P15 responsive role-based images, P16/P18 module boundaries, P11/P20 keyed subscriptions, P13/P27 only where long lists warrant it. P19 timeouts can be independent; P25 matters mainly when hosted multiuser.
6. **Small follow-ups after measurements:** P21–P24, P26 and the conditional GPU/cache/credits hypotheses above.

These are an audit roadmap, not executor-ready implementation plans. Split changes by behavior and validate each batch before expanding scope.

## Measurement and regression requirements

- Use a production build for prefetch/bundle conclusions when a build is explicitly authorized; dev mode does not represent production prefetch. Do not start another server implicitly.
- Record cold and warm navigation separately: home → title, title → episode, search suggestion → title, library next/back, settings revisit. Track request count/bytes, first useful content, loading duration and redundant upstream calls.
- Network matrix: one slow/failing addon among healthy ones, cold TMDB, unavailable Stremio, cancellation during fast scroll and account change. Measure tails as well as median; never make uncapped Promise.all the answer to every loop.
- React profiles: cast scrolling; one watched update in a populated grid; subtitle-size dragging; player time ticks with controls open/closed; 80-message fast chat. Compare commits and changed subtrees. [React Profiler](https://react.dev/reference/react/Profiler).
- CPU/GPU/energy: idle home, title, search/settings, foreground/background tabs, player hidden/visible; verify the header sleeps and animation correctness persists. Do not reopen the discontinued Windows blur-performance experiments.
- Images: narrow/wide viewport and 1x/2x DPR, byte/decode/memory changes, missing artwork fallback, multilingual posters, supplied search artwork and Back/segment image stability.
- Caches: bounded growth, account/token/config segregation, negative results not poisoning success caches, failed pending eviction, addon/token invalidation, no stale playback status or signed stream URL reuse.
- No fixed percentage, millisecond, FPS or Lighthouse gain is supported by this source-only audit.
